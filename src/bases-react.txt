Componentes permitem que a interface do usuario seja divida em partes independentes e reutilizaveis. Conceitualmente, os componentes são funções js, permitem entradas arbitrárias (props) e retornam elementos react que devem ser renderizados

Props:

    Argumentos passados para componentes react. Fluxo unidirecional (de cima pra baixo/ pai para filho) Props são imutaveis, os filhos não devem alterar os dados.
    Todos os componentes react tem que agir como funções puras em relaçãos aos seus props, não posso alterar a entrada. 
    Recebem dados dinâmicos do componente pai para tornar ele reutilizavel. São imutáveis, são acessadas por desestruturação ou acessando tipo propriedades de um objeto.

lazy initialization = bom para perfomance. React só chama a função uma vez quando o componente é montado e ignora completamente a função nas renderizações seguintes. ex: localstorage, sessionStorage, leitores de valor do dom, criar objetos grandes

- Principio da imutabilidade
Ao trabalhar com objetos mutáveis no react (objetos e arrays(objeto)), não podemos altera-los diretamente, é uma má prática. Temos que copiar o objeto em seu estado previo e recriar o mesmo.

Quando alteramos o objeto diretamente, a referencia desse objeto permanece a mesma e o react não detecta a alteração e não re-renderiza o componente. 

Context API
Contexto é uma forma de passar dados entre a arvores de componentes sem usar props drilling (passar props manualmente entre componentes até chegar em um componente abaixo na arvore)
- usados: preferencas locais e tipos de UI (toast compartilhado por toda a aplicação)
- indicado usar contexto para comaprtilhar dados considerados globais pela arvore de componentes do react, ex: usuario autenticado, idioma preferido

-criar contexto tipado - crio provider e hook com o mesmo tipo do contexto, convenção de type safety e também por segurança

-crio um hook personalizado com o contexto que quero compartilhar por toda a aplicação(o hook deve retornar exatamente o que o provider passa de valor, por convenção do typescript), nesse hook vou ter o valor inicial e a função para atualizar o valor dela

crio contexto - tipo o contexto com state e setStae - crio hook para usar o contexto - crio componente que usa o provider do contexto e o state e set state como value, o state é o tipo initialContextState constante usada/objeto literal que contem todos os dados da apliação. ela representa o estado a ser renderizado pelos componentes o os dados que vamos passar por cada componente dentro do provider

Controlled Components:
Componentes controlados é um conceito que se aplica a componentes cujo os valors são gerenciados pelo estado do react. Os dados dele são validados e atualizados pelo estado. Isso gera muitas re-renderizações

componentes controlados são aqueles onde o react controla o valor através do state, não o DOM - usamos useState() renderizamos o componente várias vezes.
- propriedades value e onChange controlam o valor atual do input e a atualização para um novo valor - usamos useState pra validar o input em tempo real, no tempo que o usuario digita. o onChange monitora cada atualizaçao, cada letra, e dispara a função pra atualziar o valor do formulario e re-renderizar o componente.

  //controlando o estado do input para capturar o valor e renderizar o componente na tela
  const [ taskName, setTaskName ] = useState(" ");

  //função para atualizar o input, pegando o valor no target em questão que é o input
  const handleChange = (event: React.ChangeEvent<HTMLInputElement>) => {
     setTaskName(event.target.value)
   }
    value={taskName}
    onChange={handleChange}

Forms não controlado = useRef() - acessa elementos do DOM - Usado em formularios grandes quando não precisamos validar o valor em tempo real- caso de uso focus 
Cria uma referência mutavel que persiste entre renderizações sem causar re-render quando o valor muda

numero.current += 2; //mudando o valor e não causa re-render
