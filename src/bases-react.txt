Componentes permitem que a interface do usuario seja divida em partes independentes e reutilizaveis. Conceitualmente, os componentes são funções js, permitem entradas arbitrárias (props) e retornam elementos react que devem ser renderizados

Props:

    Argumentos passados para componentes react. Fluxo unidirecional (de cima pra baixo/ pai para filho) Props são imutaveis, os filhos não devem alterar os dados.
    Todos os componentes react tem que agir como funções puras em relaçãos aos seus props, não posso alterar a entrada. 
    Recebem dados dinâmicos do componente pai para tornar ele reutilizavel. São imutáveis, são acessadas por desestruturação ou acessando tipo propriedades de um objeto.

State: memória do componente. como o componente reage a mudanças. atualizar wa variavel e renderizar isso na tela. o hook useSate tem uma variavel pra reter os dados entre as renderizações e uma função para atualizar a variavel e acionar o reat pra renderizar o componente. Sem efeitos colaterais no setState(), apenas funções puras

  //usando useState pra monitorar o valor da variavel e renderizar a tela com o valor atualizado

  function handleClick() {
    setNumero((numero) => numero +1)
  }

localStorage é um tipo de armazenamento do navegador que salva os dados (strings) no formato chave e valor de maneira permanente. consigo setar, ler, apagar e limpar todos os dados

localstorage é separado por origin (protocolo, host, porta) = esse mesmo conjunto compartilha o mesmo localstorage

Quer persistência real → localStorage ou cookie (podem ser enviados ao servidor)

session é parecido
Quer isolamento + mais segurança → sessionStorage
Quer segurança forte → cookie httpOnly + backend session/token
