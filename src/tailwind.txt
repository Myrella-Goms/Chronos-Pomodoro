Tailwind css:

    - Framework css, mobile first por natureza:
    - Se eu não definir nenhum breakpoint na classe, aquela estilização vai se aplicar pra mobile, tablet e desktop. Logo, se eu der um flex flex-col-reverse e não definir nenhum breakpoint, todos os tamanhos de tela teram essa configuração
 
    className="flex flex-col w-full px-9 md:px-10"
        as primeiras classes utilitárias são referentes ao layout mobile, e são sobrescritas por breakpoints a medida que a tela aumenta.

    Toda classe utilitária no tailwind pode ser aplicada condicionamente em breakpoints diferentes, na mesma div 
        ex: <div className="gap-4 md:gap-8 min-[975px]:pt-0"></div>

        breakpoints: 
        sm(40rem) - não usar sm para marcar telas mobile, a abordagem ideal é definir o que for mobile primeiro e depois sobrescrever em breakpoints maiores, 
        md(48rem), 
        lg(64), 
        xl(80), 
        2xl(96)
        equivale à = `@media (width >= 40rem)`

        shrink: propriedade que define se um elemento pode reduzir em um container flex quando falta espaço

    
    cn é quase um padrão em projetos react com tailwind que permite usarmos classes utilitárias diferentes a depender de onde chamamos o componente

        div className={cn(
            flex flex-col-reverse,
            className 
            isActive ? 'gap-4' : 'gap-10' 
        )}

tailwind v4

quando importamos o tailwind, ele define essas camadas:

@layer theme, base, components, utilities;

@import "./theme.css" layer(theme);
@import "./preflight.css" layer(base);
@import "./utilities.css" layer(utilities);

a camada de theme serve para definir os tokens que serão usados no nosso projeto, nas classes utilitárias (a depender do nome do token, ele pode ser usado por baixo dos panos pelo tailwind, no preflight)

a camada base aplica regras globais no projeto, essa camada usa o preflight que já possui regras definidas para padronizar comprotamos entre navegadores diferentes. 

    *preflight é um conjunto de estilos base projetados para suavizar inconsitências entre diferentes navegadores, como se fosse um reset.css/normalize.css.

a camada de componente cria classes para serem usadas em componentes reutilizaveis

a camada de utilities cria classes utilitiarias tailwind, usando css
